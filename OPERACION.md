# Operación del flujo

1. Comparte el enlace del portafolio únicamente en una conversación comercial pertinente.
2. El interesado revisa las muestras y puede responder en la conversación comercial donde recibió el enlace, sin tener cuenta de GitHub. Como alternativa, abre una consulta pública de servicio en GitHub: para ese formulario sí necesita cuenta y debe evitar datos privados.
3. Juan Manuel revisa la necesidad, confirma capacidad, extensión, materiales autorizados y plazo tentativo. Una consulta no es un pedido.
4. El alcance, precio, forma de pago y condiciones se acuerdan por un canal adecuado con intervención de Juan Manuel. Los documentos privados no se suben al repositorio ni a sus consultas públicas.
5. Se prepara una versión revisada y se entrega por el canal acordado. La aceptación del alcance y de la entrega se conserva de forma privada.
6. Solo Juan Manuel puede confirmar un abono disponible, sus cargos y conversión. Cerrar una consulta de GitHub no prueba un cobro.

La automatización `Revisar portafolio` se ejecuta al modificar archivos o manualmente. Comprueba enlaces locales, integridad de la demo y la selección de archivos públicos. No busca clientes, envía mensajes, cobra, acepta contratos ni tiene programación periódica. Usa un ejecutor estándar Ubuntu y permisos de lectura.

## Puesta en marcha

- Subir exclusivamente los archivos de esta carpeta, sin la carpeta del proyecto comercial.
- Mantener Issues habilitadas. El enlace del README abre el formulario `solicitud.yml`.
- Verificar el formulario con una consulta ficticia marcada como prueba. Cerrarla sin contar pedido ni ingreso.
- Compartir el enlace real solo después de comprobar que el repositorio y formulario están accesibles.
